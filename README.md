# Class-Imbalance Ablation Benchmark on the BoltzTraP Transport Database

Code, data, and results for the manuscript:

> J. M. Omar and K. Akyol, "Handling Class Imbalance in High-Throughput Materials Simulation Data: A Cross-Validated Ablation Benchmark on an Ab Initio Transport Database." Under review, *Journal of Computational Electronics*.

## What the study does

- **Data.** 9,036 inorganic compounds from the `boltztrap_mp` dataset, derived from the ab initio transport database of Ricci et al. (*Sci. Data* 4, 170085, 2017). Values refer to 300 K and a carrier concentration of 10^18 cm^-3.
- **Label.** A compound is positive (the "light-hole" class) when its hole conductivity effective mass is below 1.0 m_e, where m_e is the free-electron mass. This gives 445 positives (4.92%) and 8,591 negatives, an imbalance ratio of 19.3:1. Printed output and figures call the positive class "High-Mobility"; under the constant relaxation time approximation used by BoltzTraP, a lower effective mass implies a higher mobility.
- **Inputs.** Three n-type descriptors: `m_n`, `PF_n`, `S_n`. Two Gaussian noise columns (`Noise_1`, `Noise_2`) are added as a check that SelectKBest removes uninformative features.
- **Design.** Six pipelines (Table 2 of the manuscript), 5-fold stratified cross-validation (`random_state=42`), nested `RandomizedSearchCV` (n_iter = 30, inner cv = 3, scoring = F2), and a fixed decision threshold of 0.5. All resampling happens inside the training folds through `imblearn.pipeline.Pipeline`.

## Scope and limitations

- The inputs and the label come from the same DFT band structure and the same BoltzTraP calculation. Anyone who has the inputs for a compound also has its hole effective mass. The classifier is therefore a **benchmark for imbalance-handling strategies, not a screening tool**, and no new material is proposed.
- One dataset, one label threshold (1.0 m_e), and one set of conditions were used.
- A class-weighted XGBoost baseline (`scale_pos_weight`) was not tested.
- Folds are random, not grouped by composition. The 9,036 compounds have 7,450 distinct formulas, so polymorphs of one composition can fall in both training and test folds.

The PNG files in `figures/` are the versions used in the manuscript. `main.py` also writes supplementary outputs that the manuscript does not report: `FigS1_Radar_Chart.pdf`, `FigS2_Learning_Curve.pdf`, `Overfitting_FoldVariance.csv`, and `Learning_Curve_Data.csv`.

Figure 6 is a visualization only. For that figure, Borderline-SMOTE is applied once to the full dataset; all reported metrics use resampling inside the training folds.

## Reproducing the results

Run all commands from the repository root.

```bash
pip install -r requirements.txt
python main.py                        # Table 4, statistical tests, Figures 3 to 6
python scripts/adasyn_sensitivity.py  # Table 5
python scripts/fig1_spearman.py       # Figure 1
```

Each of the first two scripts took a few minutes on a 2-core machine.

## Reproducibility check

The stored results were produced in Google Colab; the library versions used there were not recorded. On 29 September 2026 we reran the code with the versions in `requirements.txt` (Python 3.11). The rerun reproduced exactly:

- all Table 4 metrics for Pipelines 1, 2, 3, 5, and 6;
- the feature importances in `results/Feature_Importances.csv`;
- the McNemar test for Pipeline 1 versus Pipeline 2 (b = 710, c = 173, χ² = 325.36);
- the Wilcoxon result for Pipeline 1 versus Pipeline 2 (W = 0, p_raw = 0.0625, Holm-corrected p = 0.9375);
- the ADASYN row of Table 5;
- the Spearman correlations of Figure 1 (−0.79, −0.85, 0.73).

**Pipeline 4 (decision tree) differs slightly.** The rerun gives F2 = 0.582 ± 0.022 instead of 0.578 ± 0.023, because a different tree configuration is selected in fold 2. The stored `results/` files and the manuscript report the original Colab run.

`scripts/fig1_spearman.py` reports p-values of 0.0 because they fall below the smallest number that double-precision arithmetic can represent; the manuscript reports them as p < 0.001.
